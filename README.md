# HealthSaathi

OPD clinic management for small Indian clinics, installable as a web app, in English and Hindi.

Every staff access to a patient record is explained from clinic workflow evidence (appointment,
queue token, lab order, referral, care team, break-glass). Accesses that cannot be explained are
ranked for an admin to review. Every access is written to an append-only log whose signed
checkpoints are anchored on public witnesses, and patients can verify their own access receipts in
the browser.

## Layout

| Path | What |
|---|---|
| `apps/web` | React PWA |
| `apps/api` | FastAPI app |
| `packages/e2d-core` | Explanation engine, features, scoring, Merkle ledger (Python) |
| `packages/receipt-verify` | Receipt verification (TypeScript) |
| `contracts` | Solidity contracts (Foundry) |
| `sim` | SaathiBench simulator |
| `experiments` | Experiment configs, runners and statistics |
| `infra` | Docker compose files |
| `docs` | Changelog, guides, security documents and architecture decisions |

## Quick start: the local demo

The whole app runs on one laptop with one command, with two synthetic clinics already in use.

Prerequisites: [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker
Engine with Compose v2), GNU Make and git. The images take about 3 GB of disk (more while
building). No
accounts, keys or internet services are needed after the first image download.

```sh
git clone --recurse-submodules https://github.com/vaani1127/healthsaathi.git
cd healthsaathi
make demo
```

The first run builds the images and takes a few minutes. When it finishes it prints the logins:
one password for every staff account, an authenticator key per staff account, and the patient
emails. Then open http://localhost:8080.

| Port | What |
|---|---|
| http://localhost:8080 | The web app (production build), with the API under `/api` |
| http://localhost:8080/dev/mailbox | Sign-in codes for patients (local demo only) |
| http://localhost:8081/docs | API documentation |
| http://localhost:8545 | Local anvil chain with the contracts deployed |
| localhost:5433 | PostgreSQL (`healthsaathi` / `healthsaathi`) |

Everything listens on 127.0.0.1 only.

Signing in:

- Staff: email and password from the table, then the 6 digit code. Add the printed key to
  Google or Microsoft Authenticator ("Enter a setup key"), or print the current code with
  `make demo-code EMAIL=doctor1.a@demo.healthsaathi.test`.
- Patients: open "Patient? Sign in with a code sent by email", type the email, and read the code in the dev
  mailbox.

What the demo contains: two polyclinics with every role, 50 patients and about three weeks of
activity generated by the SaathiBench simulator, including snooping, explanation forgery and
break-glass cases (the table printed by `make demo` lists where each one ended up). The worker
scores accesses every minute and anchors the audit log every 2 minutes on the local chain and in
a local git witness folder (`.demo/witness`). OpenTimestamps is not used locally and shows as
"Not configured".

Other commands:

| Command | What |
|---|---|
| `make demo` | Build and start, or start again (the data is kept) |
| `make demo-down` | Stop the demo, keep its data |
| `make demo-reset` | Stop and delete all demo data; the next `make demo` starts fresh |
| `make demo-e2e` | Browser tests against the running demo |
| `make fhir-validate` | FHIR export of 10 patients checked by the HAPI validator |

## Development setup

Requirements: Docker, Python 3.12 with [uv](https://docs.astral.sh/uv/), Node 22 with pnpm,
[Foundry](https://getfoundry.sh/) and GNU Make.

```sh
git clone --recurse-submodules https://github.com/vaani1127/healthsaathi.git
cd healthsaathi
cp .env.example .env
make install
make dev      # postgres, api on :8000, web on :5173
make lint
make test
```

## Compliance

Designed to support obligations under the DPDP Act 2023 and DPDP Rules 2025. Not legally reviewed
or certified. All data in this repository is synthetic.
